# 浏览器冒烟测试

运行 `npm start` 后，在现代 Chromium 浏览器中按以下场景验收。测试使用独立的临时观看方案，结束后删除该方案，避免改变日常配置。

## 桌面端

1. 打开 `http://127.0.0.1:8787`，确认 v1 配置自动出现在「默认方案」，刷新后房间、打开窗口、布局和独立设置保持不变。
2. 新建空方案、复制当前方案、重命名；快速切换方案，确认只有目标方案的窗口存在，旧方案声音和弹幕连接停止。
3. 在添加框输入一个已有房间、一个有效新房间和一个无效值，确认只打开首个成功解析的房间，结果对话框分别统计新增、重复和失败并可展开失败原因。
4. 首次打开、刷新和切换方案后默认选中「已开播」；状态检测完成后仅显示开播房间，不残留「没有匹配的直播间」。切换「全部」可见离线房间；按标题、主播、房间号搜索并切换筛选，确认原有顺序不变。
5. 进入批量模式，验证选择当前结果、选择已开播、打开所选、关闭窗口和带数量确认的删除操作。
6. 点击某窗口「独听」，再切换到另一窗口并退出，确认进入独听前的静音状态恢复；独听期间新开的窗口退出后保持静音。
7. 验证 `A`、`/`、`B`、`T`、`M`、`D`、`R`、`1`～`9`、`?` 和 `Esc`；焦点在输入框或下拉框时不能误触字母及数字快捷键。
8. 在已打开的房间启用提醒，依次调静音/音量、刷新播放器、关闭窗口、重开窗口、刷新页面及切换方案，铃铛都应保持开启。再关闭提醒重复操作，确认旧播放器状态不会重新开启提醒。网页端权限弹窗未处理时刷新，也应保留刚才设置的开关。
9. 对未打开的离线房间开启提醒，刷新页面后切到后台。模拟或等待房间开播，应收到一次系统通知（网页端需已授权）；后续状态检查不重复通知，直到房间再次下播、开播。关闭提醒后该房间不再后台轮询。
10. Chrome 扩展播放含音频时间戳重叠或间隔的直播，确认不再输出已由 remuxer 自动修正的 `MP4Remuxer Dropping 1 audio frame` / `Large audio timestamp gap detected` 警告；音画同步修正继续生效，其他警告和真实播放错误仍可见。

## 移动端（390 × 844）

1. 刷新页面，确认直播间抽屉默认关闭，内容区域左边缘为 `0` 且宽度为完整视口宽度。
2. 点击顶栏「直播间」，确认抽屉和遮罩出现；点击遮罩、房间或按 `Esc` 均会关闭抽屉。
3. 进入批量模式，确认复选框与操作栏完整可见，操作栏固定在抽屉底部。
4. 使用上下箭头调整房间顺序，关闭并重新打开抽屉、刷新页面后顺序保持不变。
5. 确认窗口控制栏始终可操作，放大窗口不会产生横向的 2×2 跨列布局。
